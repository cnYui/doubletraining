三个智能体，同一块屏幕

DoubleTraining 记录你的每一组，DoubleRunner 守住你的步频，WorkHealthier 盯着你怎么坐。 三个独立项目，跑在同一套运行时、同一块 480 × 352 单绿屏、同一副镜腿手势上。

5 个 Page 3 个仓库，均在 github.com/cnYui 132 个 Node 测试全部通过 严格项目校验 × 3 全部干净 尚未达到发布标准
共同的出发点

每一个都在做手机结构上做不到的事

眼镜本来就会用语音回答问题。三个智能体的范围都被限定在通用语音助手做不到的事上： 记住你的数字、读取本来就绑在你头上的传感器，以及看住你自己看不见的东西——你自己。

DT记忆

每一次点击都是一组被记下的训练，存在眼镜上。下一次训练从真实数字开始，而不是靠回忆； 总结页还能把今天和上一次训练同一个部位的成绩放在一起比。

DR头上本来就有的传感器

跑步步频通常要手表或足踏传感器。戴在头上时，每一步都以一次点头的形式到达陀螺仪， 所以眼镜不需要额外硬件就能读出步频，并据此打拍子。

你看不到自己的头部角度，也不知道自己已经凑到屏幕多近。眼镜正好在这个测量必须发生的位置上， 而且只在这件事已经错得够久时才开口。

平台拒绝做到的事

AIUI 0.17 里任何地方都没有振动 API

「让镜腿以 180 spm 震动」是最直觉的设计，而它做不出来：文档、样例和运行时里都没有触觉入口。

DR · 拍子改成 1200 Hz 的短音，每第四拍加重，再加上亮 110 ms 的圆点。 车流噪声里就只剩圆点在承担。
没有 ToF、没有激光、没有红外

一颗 1200 万像素摄像头和一个 IMU。距离只能从图像里来，而图像里需要一个已知尺寸的东西。

WH · 显示器上贴一张打印的二维码标记，按成像大小测距，一次校准抵掉打印误差。
双击永远到不了 Page

用 Page 级按键日志确认过：只有系统主页会响应。这个手势在真机上是真的，但离开真机就无法测试。

三个项目 · 所有「返回」都留给宿主，也没有任何破坏性操作挂在双击上。
new Date(y, m, d) 不能信

同一段调用在两次运行之间返回不同结果；而一张对话卡片曾经打开到 20 天之后—— 因为一个以秒为单位的 UTC 偏移被当成了分钟。

DT · 所有日期运算走 1970-01-01 以来的整数天，偏移统一归一化， 「今天」只从 Date.now() 来。
模板引擎会丢行，也会忽略 class

<page> 根节点上的动态 class 不起作用（黑屏），带 ink:for 的那个元素上取不到循环变量，被重建的 ink:if 里的行再也回不来。

三个项目 · 根节点只用静态 class，每个循环都包一层 <block>，面板保持挂载、靠数据绑定的 class 切换。
浏览器面板被遮住时一帧都不渲染

面板不在前台时，运行时报 hidden 并停止动画，于是导入会卡在解包中途、预览冻结。

流程 · 每次截图都让 Studio 保持在前台。这份 deck 里的每一张屏都是这样拍的。
