Pick a date · the wheel04 / 12

A date wheel instead of a month grid

A full calendar is unreadable at 480 × 352, so the selected day is enlarged with two neighbours on each side.

↑swipe fwd

Swipe forward goes to the previous day, swipe back to the next, tap opens it.

Every row carries its focus and state: Done, 12 / 14 sets, Rest day, Not planned.

Week 2 / 5 counts planned training days Monday to Sunday. Range: 60 days each way.

Rest timer · built, parked07 / 12

A rest countdown between sets

Implemented and tested earlier in Studio, then switched off at the product owner's request so a tap only ticks the box. One flag brings it back: REST_TIMER_ENABLED = true.

Per-exercise rest: 120 s for compound lifts, 60–90 s for isolation.

Swipe to change the next set's weight by one plate step (2.5 kg barbell, 2 kg dumbbell) — the moment you know it was too light.

Tap or nod skips rest; double tap undoes the set just logged. Nod is only listened for while resting, so a nod under the bar can't log anything.

The countdown survives the Page being hidden: it tracks a deadline, not a ticking counter.

Chat card · open issues08 / 12

The chat card caught two bugs

Studio can also run a Page inside the conversation as a 448 × 150 card. Capturing it for this deck exposed two problems the full-size preview hides.

The compact layout never switched on

The Page drew the top of its full layout. The max-height: 240px rule that should collapse it to the current exercise did not match inside the card.

Find a size signal the card reports reliably, then check on the glasses.

The date ran 20 days ahead

On Fri, Sep 11 the card opened Thu, Oct 1. 28,800 minutes is exactly 20 days, and −28,800 is UTC+8 counted in seconds, so this host most likely reports the timezone offset in seconds while todayKey() expects minutes.

Ignore offsets beyond ±14 hours.

Input · measured, not assumed09 / 12

What the temple actually sends

Recorded from the Page's own key logs in the AIUI Studio 1.1.0 glasses simulator.

GestureKeys the Page receivesDouble Training
TapGlobalHook → EnterOpen the day · log a set · mark cardio done
Swipe forwardGlobalHook → ArrowUpPrevious day · previous exercise
Swipe backGlobalHook → ArrowDownNext day · next exercise
Double tap— nothing reaches the PageDesigned as "back to calendar"; untestable in the simulator

GlobalHook arrives before every gesture. Treating it as a tap would fire twice per touch, so the Pages act on gesture keys only.

A lone GlobalHook — what real glasses may send — becomes one tap after 280 ms; one that echoes a gesture key within 450 ms is ignored.

Key order on physical glasses is still to be confirmed.

Engineering · what the simulator taught us10 / 12

Six runtime surprises, all handled in code

new Date(y, m, d) drifted by weeks to a month between calls

Integer day numbers since 1970-01-01; "today" only from Date.now().

Loop variable unbound on the element carrying ink:for

Every loop is a <block ink:for> around the real element.

Rows vanished when an ink:if panel was re-created

All panels stay mounted; a data-bound class shows one.

A dynamic class on the <page> root was ignored — black screen

Static root class; dynamic classes on ordinary views.

Full-size preview still reports the _current target

Compact layout keyed to max-height: 240px.

A hidden browser pane renders zero frames and stalls imports

Keep Studio visible while testing; captures taken live.
